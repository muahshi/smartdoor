# CEO Weekly Routines

The CEO's planned weekly operating cadence, once active in a future
phase. This is the CEO's primary recurring cadence — see
`DAILY_ROUTINES.md` for why daily is intentionally thin, and
`MONTHLY_ROUTINES.md` for the longer-horizon cadence above this one.

## The Weekly Cross-Domain Check-In

Per `EXECUTIVE_MEETING_GUIDE.md`'s "Weekly Cross-Domain Check-In"
section: assemble what each sibling executive's own
`*/WEEKLY_ROUTINES.md` would have surfaced that week (CTO bug triage and
release status, COO ticket/fulfilment trend, CFO weekly revenue
movement, CMO campaign/content/SEO status, CPO `feature_requests`
movement), and apply `PRIORITY_MANAGEMENT.md` to produce a single
founder-attention ordering across all five.

## Steps

1. Read each sibling executive's real, current weekly signal — never
   assume last week's state still holds.
2. Check for any new cross-domain dependency surfaced this week (e.g. a
   CTO release that has downstream COO or CFO implications, per each
   domain's own `INTER_EXECUTIVE_COMMUNICATION.md` handoff patterns).
3. Apply `DECISION_FRAMEWORK.md` to any genuine conflict found between
   two domains' weekly signals.
4. Produce a single ordered list of what deserves the founder's
   attention first this week, with citations, per
   `PRIORITY_MANAGEMENT.md`.
5. Flag, don't resolve, anything that would require founder-level
   approval per any sibling's `AUTHORITY_MATRIX.md`.

## What Changes Week to Week

Unlike `DAILY_ROUTINES.md` (reactive only) and `MONTHLY_ROUTINES.md`
(strategic/health-focused), the weekly cadence is where the CEO's core
value — cross-domain priority ordering — is exercised most regularly.
This is the cadence a founder would realistically use to decide "what do
I personally look at this week across everything I'm running."

## Current Status

As of Phase 8, none of this runs — no domain executive is reading live
weekly data yet (`ai/integrations/` doesn't exist), and this document
specifies the intended cadence for once that layer exists.
