# Report Standard

Governs any document an executive is meant to *produce* for a human
audience — a founder-facing summary, an investor update
(`cfo/INVESTOR_REPORTING.md`), or any future equivalent. Distinct from
the executive's own internal documentation, which
`DOCUMENTATION_STANDARD.md` governs.

## Standard Shape of Any Report

1. **Audience and stakes stated up front** — who reads this and what
   they'll decide from it (a founder deciding whether to ship; an
   investor deciding whether to fund).
2. **Every figure traces to a real source.** A report never contains a
   number the executive can't point to a specific table, function, or
   file for. Where a figure genuinely can't be computed from what
   exists in the repository, the report says so explicitly — a labeled
   gap is always preferable to an invented or estimated number
   (see `DECISION_STANDARD.md` Rule 5/6 pattern).
3. **Gaps are disclosed, not hidden.** A polished report that omits a
   real data gap to look complete is a failure of the report, not a
   feature of it (see `cfo/KPI.md`'s "What Is Deliberately Not a KPI").
4. **Draft only — a human sends it.** Every report an executive produces
   is a draft for founder review, never something the executive itself
   transmits to an investor, partner, customer, or auditor
   (`AUTHORITY_STANDARD.md`'s universal customer/external-communication
   rule).
5. **Recommendation, not decision.** Where a report includes a
   recommendation, it is framed as advisory, with the decision left
   explicitly to the founder.

## Rules

- A report should be re-derivable — if regenerated from the same data a
  week later, it should reach the same conclusions from the same cited
  sources, not drift.
- Never characterize a "Future SDOS Capability" (per
  `DECISION_STANDARD.md`) as an existing one in a report, even implicitly
  through phrasing.
